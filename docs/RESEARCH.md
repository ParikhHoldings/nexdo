# Research

## Competitors / alternatives
- traditional task managers
- AI add-ons layered onto project/task tools
- founder/operator workflow systems built from docs, spreadsheets, and chat tools
- agent workspaces and MCP-connected tools that can create, update, annotate, or complete tasks

## Insights
- productivity software often overpromises intelligence and underdelivers execution leverage
- differentiation for Nexdo must come from concrete workflow behavior, not naming alone
- the existing codebase already supports a more concrete story than "AI task manager" if verification confirms the flows
- repo/deploy/product truth needs to be explicit before stronger go-to-market moves
- external-agent interoperability could be a sharper wedge than another human-only task list
- deterministic local fallbacks make the demo more resilient, but they should be positioned as demo/provider-failure behavior rather than the final intelligence layer

## Open questions
- what exact task workflow should Nexdo own first?
- what segment feels the most acute pain from current task-manager limitations?
- what MVP behavior would make the product immediately feel more alive than a list app?
- which bounded execution types are useful enough for early users without overpromising autonomy?
- what proof is needed before MCP/ChatGPT Actions become a front-door marketing claim?
- what monitoring is needed to catch future framework/security advisories early?

## Opportunities
- build the operating truth early so Nexdo can move from concept into active product execution
- use founder/operator execution pain as a likely initial wedge
- use task metadata as the product moat: context, people, urgency, energy, and agent-readable state
- demonstrate agent interop through a small set of reliable tools instead of a broad integration promise
